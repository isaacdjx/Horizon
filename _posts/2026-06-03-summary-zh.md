斯坦福法学院发表的一项新研究发现，在盲评中，法学教授们更倾向于 AI 生成的一年级合同法问题反馈，而非教授自己撰写的反馈。该研究涉及 16 位教授，每位教授进行了约 3000 次比较，论文于 2026 年 6 月发布。 这项研究凸显了大语言模型作为专业教育辅导工具的巨大潜力，有望通过 AI 生成的指导补充教授反馈，从而降低法学教育的成本。同时，它也引发了关于 AI 进入长期被视为高度训练人类专家专属领域的更广泛讨论。 该研究仅包含 16 位教授作为评估者，且各教授间的评分结果差异极大，引发了关于统计效力的质疑。研究范围仅限于常见的一年级合同法问题，专注于 AI 作为辅导工具的潜力，而非取代律师的法律执业能力。

hackernews · berlianta · 6月2日 23:43 · [社区讨论](https://news.ycombinator.com/item?id=48377761)

**背景**: GPT-4 等大语言模型已在律师资格考试等标准化法律考试中展现出强大的表现，促使研究者开始探索其在法学教育中的应用价值。法学院教学传统上高度依赖教授与学生之间的互动和个性化反馈，这种模式资源消耗大且难以规模化。盲评研究是比较 AI 与人类表现的常见方法，评审者在不知道输出来源的情况下进行评估，以尽量减少偏见。斯坦福法学院的 CodeX 中心一直是研究 AI 与法律实践交叉领域的领先机构。

## [开源工具让 Linux 将 Nvidia GPU 显存用作交换空间](https://github.com/c0dejedi/nbd-vram) ⭐️ 6.0/10

一个名为 nbd-vram 的新开源项目提供了一个 Linux 守护进程，通过 CUDA 驱动 API 分配 Nvidia GPU 显存，并利用 NBD（网络块设备）协议通过 Unix 套接字将其暴露为交换设备，使内存不足的系统能够利用闲置显存作为额外的交换空间。 该工具解决了笔记本用户的一个实际痛点——这些用户的内存焊死无法升级，但同时拥有大量闲置显存的 GPU，该工具提供了一种比 SSD 交换更快的替代方案，将原本浪费的硬件资源利用起来。这也反映了随着现代笔记本硬件升级性日益受限，人们在创造性利用资源方面的趋势。 社区测试显示，在 RTX 3070 笔记本上顺序吞吐量仅约 1.3 GB/s，远低于 PCIe 4.0 x16 理论上的 64 GB/s，这可能是因为该工具绕过了 Nvidia 受限的 P2P API（仅限 Quadro 和数据中心 GPU），改用 CUDA 内存拷贝函数，引入了较大开销。此外，社区还对 Wayland 合成器下的显存回压问题表示担忧，因为动态缓冲区分配可能在显存不足时导致桌面崩溃。

hackernews · tanelpoder · 6月2日 22:55 · [社区讨论](https://news.ycombinator.com/item?id=48377404)

**背景**: NBD（网络块设备）是一种 Linux 协议，允许计算机通过简单的客户端-服务器模型将远程或虚拟存储设备当作本地物理磁盘使用。Linux 中的交换空间是一种基于磁盘的内存机制，当物理内存耗尽时，内核会将不常用的内存页转移到较慢的存储设备上。GPU 显存（VRAM）是显卡上的高速内存，主要用于图形渲染和计算任务，但在未运行 GPU 密集型工作负载的系统上往往处于闲置状态。Nvidia 的 CUDA 驱动 API 提供了对 GPU 资源的编程访问，但某些直接内存访问功能仅限于专业级 Quadro 和数据中心 GPU 产品线。

## [Simon Willison 发布 Datasette Agent 的 MicroPython 沙箱插件](https://simonwillison.net/2026/Jun/2/datasette-agent-micropython/#atom-everything) ⭐️ 6.0/10

Simon Willison 发布了 datasette-agent-micropython 0.1a0 alpha 版本，这是一个利用编译为 WebAssembly 的 MicroPython 作为沙箱，让 Datasette Agent 能够安全地生成和执行 Python 代码的插件。Willison 提到 GPT-5.5 目前未能突破该沙箱，表明其安全特性颇具潜力。 安全的代码执行是 AI 智能体面临的一个关键未解难题——如何让大语言模型编写并运行代码而不危及系统安全。该项目展示了一种基于 WebAssembly 的轻量级沙箱方案，可能会影响其他 AI 智能体框架处理安全代码执行的方式。 该插件基于 Simon Willison 的 micropython-wasm 库构建，使用自定义的 MicroPython WASI 制品，通过 wasmtime Python 运行时执行，每次运行都会创建一个全新的隔离实例。这是一个早期 alpha 版本（0.1a0），虽然 GPT-5.5 的沙箱逃逸测试结果令人鼓舞，但项目仍处于初始阶段，文档有限。

rss · Simon Willison · 6月2日 19:28

**背景**: Datasette 是一个用于探索和发布数据的开源工具，Datasette Agent 是其 AI 驱动的助手，能够编写和执行 SQL 查询来分析数据。MicroPython 是一个为受限环境设计的精简 Python 实现，当编译为 WebAssembly（通过 WASI）后，它运行在一个严格隔离的虚拟机中，无法直接访问宿主文件系统、网络或操作系统。这种沙箱方案对 AI 智能体尤为重要，因为它们越来越需要执行大语言模型生成的代码，但如果代码以完整的系统权限运行，则面临严重的安全风险。

## [Simon Willison 发布 micropython-wasm，通过 WebAssembly 实现沙箱化 Python 执行](https://simonwillison.net/2026/Jun/2/micropython-wasm-2/#atom-everything) ⭐️ 6.0/10

Simon Willison 发布了 micropython-wasm 0.1a0，这是一个 alpha 阶段的软件包，将经过轻度定制的 MicroPython WebAssembly 构建与 wasmtime 封装器捆绑在一起，实现沙箱化的 Python 代码执行。该项目作为 Python 沙箱化的早期实验已在 GitHub 上发布。 沙箱化代码执行在 AI 和大语言模型工具调用场景中变得越来越重要，这些场景需要安全地运行不受信任的代码，而该方案利用 WebAssembly 固有的安全模型来隔离 Python 执行，无需复杂的容器配置。如果项目成熟，它可以为 AI 智能体、在线代码运行环境和插件系统等应用提供一种轻量级、可移植的安全 Python 代码执行方案。 该软件包目前处于 alpha 阶段（0.1a0），这意味着它仍处于实验状态，在支持的 Python 特性和标准库覆盖范围方面可能存在较大限制。它使用 wasmtime 作为 WebAssembly 运行时，这是由 Bytecode Alliance 开发的生产级独立 WASM 运行时。

**背景**: MicroPython 是为微控制器等资源受限环境设计的精简版 Python 3 实现，提供 CPython 标准库的一个子集，内存和性能需求显著降低。WebAssembly（WASM）是一种二进制指令格式，能在沙箱化的执行环境中实现接近原生的性能，最初为浏览器设计，但越来越多地被用于服务器端和独立应用。Wasmtime 是 Bytecode Alliance 开发的独立 WebAssembly 运行时，支持 WASI（WebAssembly 系统接口），允许 WASM 模块以受控方式访问系统资源。Simon Willison 是 Python 生态中的知名开发者，Datasette 和 django-sql-dashboard 的创建者，也是 AI 工具和开发者体验领域的重要人物。
